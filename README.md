# One User, One Agent

**Author:** Rajveer Sharma
**Date:** 19 Oct 2026

One agent per viewer. On every app open it works out what is known about the viewer, from which source and how fresh. It then picks one measurable goal, or decides there is none, and changes the home page (plus at most one planned message) or deliberately does nothing. An independent verifier checks every decision before it is published. After the replay, each goal is judged from attributable signals, and the agent is compared with the randomized holdout.

No API key is needed. The default model provider is a deterministic mock that also replays the pack's model faults.

## Setup

Requires Python 3.11+.

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -e ".[dev]"
```

Unzip the data pack so that `./pack/data/events.jsonl` exists, or point `--pack` at it. The pack is git-ignored because it is treated as personal data (brief §7).

## Run everything: one command

```bash
python -m ott_agent run --pack ./pack --out ./sample_run
```

This takes about 40 s and runs three steps:

1. Replay the trigger day on a virtual clock, with live events, control events and model faults.
2. Run the pack's simulator on the published actions.
3. Judge the outcomes and write the impact, latency and pilot reports.

To rerun with another simulator seed, add `--seed <name>`. Everything else stays the same.

## Outputs (`sample_run/`)

The repository includes the outputs the brief asks for: `decisions.jsonl`, `actions.jsonl`, `outcomes.jsonl`, `viewer_state/`, `latency_report.json`, `impact_report.md` and `final_report.md`. The rest are regenerated by `run`.

| File | What it contains |
|---|---|
| `decisions.jsonl` | One decision per trigger delivery, including NO_ACTION with its reason. Each one records the goal and the candidates considered, dialect and conflicts, evidence with age, assumptions, confidence and its reason, checks, timing and status. |
| `actions.jsonl` | What reached viewers: home pages, plus messages that survived a final re-check. This is the simulator's input format. |
| `outcomes.jsonl` | Goal verdicts (succeeded / failed / inconclusive), with the signal and the rule version used |
| `viewer_state/<user>.json` | Each viewer's durable state: the facts snapshots, decisions, actions, goal history, outcomes and learnings |
| `impact_report.md`, `impact.json` | Agent arm vs holdout (intention-to-treat, 95% CIs), per-goal breakdown, abstention check, the biased comparisons, and the pilot re-analysis |
| `latency_report.json` | Trigger-to-publish latency, overall and per stress window; calls per decision; fallbacks |
| `final_report.md` | Summary, data issues found, surprise handling, and one viewer walked from app open to outcome |
| `control_log.jsonl` | Every reaction to a live or control event, with the viewers it touched |
| `security_log.jsonl` | Quarantined catalogue text and rejected model claims |
| `sim/` | Simulator output (`outcome_events.jsonl`, `simulator_report.json`) |

## Other commands

```bash
python -m ott_agent load    --pack ./pack                      # validate the pack, print counts
python -m ott_agent facts   --trigger <event_id>               # what the agent knew at that trigger
python -m ott_agent decide  --trigger <event_id>               # decide + verify one trigger, print the record
python -m ott_agent explain --viewer U-00649 [--at <ISO time>] # a viewer's state at any moment (after `run`)
python -m ott_agent replay | simulate | report                 # the three steps of `run`, separately
```

`explain` reads `sample_run/tmp/state.db`, which `run` creates (it is git-ignored).

## Tests

```bash
pytest
```

154 tests. They run on a small hand-built pack. `tests/test_sample_run_invariants.py` also re-checks every hard rule against `sample_run/` and the real pack when both are present, and skips otherwise.

| Required by the brief | Tests |
|---|---|
| Late or duplicate trigger | `test_duplicate_trigger_creates_one_action`, `test_stale_offline_trigger_is_not_a_live_session`, `test_fresh_triggers_jump_ahead_of_stale_ones_under_backlog` |
| Conflicting source | `test_dialect_conflict_uses_app_setting_and_keeps_conflicts_visible`, `test_purchase_event_beats_snapshot_but_only_once_it_has_arrived`, `test_profile_duplicate_*` |
| Tool failure | `test_model_timeout_falls_back_to_rules_without_retry`, `test_malformed_model_json_is_retried_once_then_rules`, `test_store_outage_means_no_action*`, `test_degraded_store_read_timeout_uses_cache_home_page_only` |
| Corrected goal rule | `test_rule_correction_targets_only_affected_open_goals`, `test_judge_applies_a_rule_correction_from_its_effective_time` |

## Optional real model

```bash
pip install -e ".[claude]"
python -m ott_agent run --pack ./pack --out ./run_claude --provider claude
```

This is off by default and was not used for the submitted run. It sends only pseudonymised, derived features (no user id, no event or catalogue text). Use it only with an account whose data-retention terms suit personal data.

## Layout

```
config/        agent.toml (budgets, thresholds, planning, model), goal_interpretations.toml (written assumptions)
src/ott_agent/ pack/ (load + validate)  state/ (facts, resolver, store)  agent/ (planner, page, messages, advisor)
               verify/ (independent checks)  models/ (mock, faults, optional real)  replay/  measure/  audit/
tests/         unit, scenario and end-to-end tests
```
